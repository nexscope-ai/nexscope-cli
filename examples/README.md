# Compare your own data

Download the [CSV template](products-template.csv), [CSV sample](products-sample.csv),
[JSON sample](products-sample.json), [JSON schema](products.schema.json) and
[field descriptions](fields.json). All sample products are fictional.

`product_id` and `title` are required. Identifiers stay strings and are unique
within a market. Price needs an explicit currency; rating needs a positive scale.
Unknown values stay unknown. Additional columns are retained. No cross-market,
cross-currency or cross-scale ranking is inferred.

```sh
nexscope report compare --input products-sample.csv --format html --out my-comparison.html
nexscope report compare --input products-sample.json --format csv --out my-comparison.csv
nexscope report compare --input products-sample.json --format markdown --out my-comparison.md
```

Run in a writable directory and use new output names. The CLI saves exact input,
row provenance and hashes beside each report. Keep the evidence directory with
the report when moving it. These commands need no credentials, keyring, LLM or
network; there is no implicit upload or refresh.

View the generated [HTML](comparison.html), [CSV](comparison.csv) and
[Markdown](comparison.md) reports. The [invalid CSV](invalid-products.csv) and
[expected error](invalid-products-error.json) demonstrate a missing currency.
Fix every reported row instead of silently dropping it.

Local limits are 10 MiB raw input / 10,000 products, 32 MiB normalized datasets
and 64 MiB evidence bundles. The three-product live pilot limit does not apply
to user imports. The automated capacity tests exceed three rows and include
10,000-row and near-size-limit inputs. These are technical limits, not a paid gate.

The runtime reads package resources. These public examples are generated by
`scripts/build_examples.py`; it does not run an online query. To update examples,
generate them in a clean staging checkout and review the input/report/evidence diff.
